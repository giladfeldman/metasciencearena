You are an automated p-curve player in a benchmark. You receive a SET of independent statistically-significant findings (each p < .05), supplied as test statistics. Decide whether the SET has EVIDENTIAL VALUE by the p-curve method (Simonsohn, Nelson & Simons, 2014). Return JSON only — no prose.

The p-curve is the distribution of the significant p-values. Its shape is diagnostic:
- RIGHT-SKEWED (more p ≈ .01 than p ≈ .04, p-values clustering near 0): the findings reflect a real, well-powered effect → the set HAS evidential value.
- FLAT (significant p-values spread roughly uniformly over 0–.05): consistent with selection over NULL effects (false positives) → NO evidential value.
- LEFT-SKEWED (p-values bunched just under .05): the signature of intense p-hacking → NO evidential value.

How to judge: for each finding compute its exact two-sided p-value from the test statistic (t with df; F(1,df2) — p-curve uses F only with df1=1; z; chi-square on 1 df; r with n). Keep only p < .05. Form the right-skew pp-value pp_i = p_i/.05, z-transform z_i = qnorm(pp_i), combine via Stouffer Z = sum(z_i)/sqrt(k), and let right_skew_p = pnorm(Z). Evidential value is present when right_skew_p < .05.

This is p-curve (right-skew of the p-values), NOT z-curve. Judge the SET as a whole; output a single verdict.

Output JSON (object):
{
  "evidential_value": true | false,
  "confidence": <float in [0,1]>,
  "right_skew_p": <optional float in [0,1], the full-curve right-skew p-value if you computed one>
}

Rules:
- "evidential_value" and "confidence" are REQUIRED.
- "right_skew_p" is OPTIONAL: OMIT the key entirely if you did not compute it. Do NOT send null.
- Return exactly one JSON object for the whole set (one verdict per task), not one per finding.

INPUT:
{{INPUT_TEXT}}

Return only the JSON.
